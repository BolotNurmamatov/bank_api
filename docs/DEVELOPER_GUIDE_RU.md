# 📘 Документация разработчика (Developer Guide)
**Проект:** API Bank Dashboard (Агрегатор банковских счетов Red Petroleum)

Этот документ предназначен для быстрого погружения новых разработчиков (Frontend, Backend, DevOps) в архитектуру и принципы работы приложения.

---

## 🏗 1. Архитектура и Инфраструктура

Проект состоит из двух основных сервисов, которые общаются друг с другом локально:

- **Frontend (Next.js, TypeScript, TailwindCSS)**
  - Запускается на порту `3000`.
  - Отвечает за пользовательский интерфейс, отрисовку графиков и авторизацию.
- **Backend (FastAPI, Python, SQLAlchemy)**
  - Запускается на порту `8000`.
  - Отвечает за логику общения с банковскими API, сбор данных и формирование отчетов.
- **База данных (ClickHouse)**
  - Backend использует SQLAlchemy для подключения к ClickHouse (`clickhouse://`). 
  - В БД хранятся исторические срезы остатков на счетах и логи активности пользователей.

### 🛡 Внутренний Proxy (Критически важно!)
Архитектура спроектирована так, чтобы **Backend был полностью закрыт от интернета**. 
1. Пользователь обращается к сайту (через Nginx). Nginx проксирует трафик *только* на Frontend (порт 3000).
2. Когда Frontend-у нужны данные, он делает запрос на собственный API (например, `/api/backend-proxy?path=/dashboard`).
3. Специальный обработчик в Next.js (`frontend/src/app/api/backend-proxy/route.ts`) проверяет авторизацию пользователя и делает скрытый HTTP-запрос к FastAPI (`127.0.0.1:8000`), подставляя в заголовки секретный пароль `INTERNAL_API_SECRET`.
4. FastAPI принимает запросы только если в заголовке есть правильный `INTERNAL_API_SECRET`.

## 🔐 2. Авторизация (Google OAuth)

Используется встроенный провайдер `next-auth`. 
- Вход разрешен **только** для сотрудников корпоративного домена `@redpetroleum.kg`. Эта проверка встроена в коллбэк авторизации во Frontend.
- Все ключи доступа (Client ID, Client Secret) задаются в переменных окружения (`.env` или `ecosystem.config.js`).

---

## 🏦 3. Интеграция с банками и Фильтрация

Логика общения с API банков находится в `backend/services/`. 
Каждый банк вынесен в отдельный модуль:
- `aiyl.py` (Айыл Банк)
- `optima.py` (Оптима Банк)
- `eldik.py` (Элдик Банк)

### Как работает фильтрация счетов:
Приложение не забирает в общую статистику *все* счета компании из банков (так как там могут быть транзитные или неактивные счета).
Вместо этого мы явно указываем нужные счета в файле `.env` (или в настройках окружения):

```env
# Пример для Элдик Банка
ELDIK_BANK_ACCOUNTS="1299003132398787, 1299003131231959"

# Пример для Оптима Банка
OPTIMA_ACCOUNTS="1350100022064496, 1350100025753227"
```
Код (например, в `eldik.py`) парсит эту строку и отбрасывает любые счета, номера которых нет в этом списке.

## ⏱ 4. Фоновый сборщик данных (Scheduler)

За сбор исторических данных отвечает скрипт `backend/scheduler.py`.
- Это отдельный Python-процесс, работающий в бесконечном цикле.
- Раз в **20 минут** он дергает функцию `update_banks_in_db()` из `bank_api.py`.
- Функция опрашивает все банки и сохраняет актуальные балансы в ClickHouse. 
- На основе этих срезов на дашборде строится график изменения балансов.

## 🚀 5. Деплой и Эксплуатация (Windows Server)

Приложение развернуто на Windows Server (`10.45.12.47`).

### PM2 (Менеджер процессов)
Для поддержания работы используется утилита PM2 (Node.js). Конфигурация описана в файле `ecosystem.config.js` в корне проекта.
PM2 управляет тремя процессами:
1. `api_bank_frontend` (Next.js)
2. `api_bank_backend` (FastAPI)
3. `api_bank_scheduler` (Python Scheduler)

**Полезные команды PM2:**
```powershell
pm2 status       # Посмотреть статус всех процессов
pm2 restart all  # Перезагрузить проект (нужно делать после обновления кода)
pm2 logs         # Посмотреть логи в реальном времени
```

### Nginx (Веб-сервер)
Nginx установлен в корень диска (обычно `C:\nginx\`).
Он занимается терминацией SSL (HTTPS) на домене `redfin.redpetroleum.kg` и редиректит трафик на локальный порт Next.js.
Если вы меняете `nginx.conf` в репозитории, не забудьте скопировать его в папку `C:\nginx\conf\` на сервере.

**Перезагрузка Nginx:**
```powershell
cd C:\nginx
.\nginx.exe -s reload
```

## 🛠 6. Руководство: Как добавить новый Банк

Если компании потребуется добавить интеграцию с новым банком (например, "Демир Банк"), выполните следующие шаги:

1. **Создайте сервис:** 
   Добавьте файл `backend/services/demir.py`. Напишите функцию `fetch_demir_accounts()`, которая ходит в API банка и возвращает кортеж: `(total_balance, account_count, status_string, accounts_list_of_dicts)`.
2. **Зарегистрируйте банк:** 
   В файле `backend/services/bank_api.py` импортируйте вашу функцию и добавьте ее вызов в `fetch_bank_data()`. Добавьте результат в итоговые массивы `banks_summary` и `all_accounts`.
3. **Настройте Frontend (UI):** 
   - Добавьте логотип банка в константу `BANK_LOGOS` (файлы `frontend/src/app/page.tsx` и `frontend/src/app/banks/page.tsx`).
   - Добавьте цвет для графика банка в константу `BANK_COLORS` (`frontend/src/app/reports/page.tsx`).
4. **Добавьте ключи в `.env`:** 
   Пропишите API-ключи и список счетов нового банка в `ecosystem.config.js` и на сервере.
